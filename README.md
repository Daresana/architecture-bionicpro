# BionicPRO

Проектная работа спринта 9. В приложении на React можно войти через Keycloak и скачать JSON-отчёт по своим протезам.

## Запуск

Для запуска нужен Docker Desktop в режиме Linux-контейнеров. Команду выполнить из папки проекта:

```bash
docker compose up -d --build
```

1. Открыть http://localhost:13000.
2. Войти как `prothetic1`, пароль `prothetic123`.
3. В Airflow по адресу http://localhost:18081 войти под `admin` / `admin`. Дождаться статуса `success` у DAG `prosthesis_reports`.
4. Вернуться в приложение и нажать `Download Report`. Скачается отчёт за вчерашний день по UTC.

Учебные пользователи:

| Логин | Пароль | Доступ к отчётам |
|---|---|---|
| `prothetic1` | `prothetic123` | Протезы 101 и 102 |
| `prothetic2` | `prothetic123` | Протез 201 |
| `prothetic3` | `prothetic123` | Протез 301 |
| `user1` | `password123` | Нет |

Админка Keycloak: http://localhost:18080, логин и пароль `admin` / `admin`.

Измерения за семь предыдущих дней создаются при первой инициализации базы. Новые измерения автоматически не добавляются. Если DAG обработал день без измерений, в отчёте будет пустой список `prostheses`.

Пароли учебные, для локального запуска. Сервисы доступны только с этого компьютера.

Остановить контейнеры с сохранением данных:

```bash
docker compose stop
```

## API

Запрос готового отчёта:

```http
GET /reports?date=YYYY-MM-DD
Authorization: Bearer <access_token>
```

Если не передать `date`, берётся вчерашний день по UTC. Можно передать `userId`, но он должен совпадать с `sub` токена текущего пользователя.

Без корректного токена API вернёт `401`, без нужной роли или при запросе чужого пользователя — `403`. Для ещё не обработанного дня вернётся `409`, при недоступности хранилища — `503`.

## Файлы

- `diagrams/task1-security.drawio` — схема SSO и вход через PKCE.
- `diagrams/task2-reports.drawio` — схема отчётов и витрины данных.
- `airflow/dags/reports_dag.py` — ежедневная обработка данных в Airflow.
- `api/` — API отчётов на ASP.NET Core.
- `clickhouse/`, `db/` — таблицы витрины и учебных источников данных.

BFF и региональные IdP показаны на диаграмме как предлагаемая архитектура. В приложении используется SPA с PKCE S256.
